## 结构（按顺序）

`角色 → 任务 → 输入 → 约束 → 输出格式 → 示例 → 失败处理`

- 用正向指令描述「要做什么」；必须否定时同时给出替代行为（不要只写「不要啰嗦」）。
- 输出格式给明确模板或 JSON Schema，字段名固定、不要同义混用。
- 关键约束放在**开头和结尾**，长上下文不要埋在中间。
- 给 1～2 个 few-shot 示例，其中一个必须是边界 / 反例。
- 明确失败与信息不足时该怎么做（说「不确定」、请求补充、返回固定错误结构）。

## 优化与验收

- 先问「哪条输出不达标」，再定位到具体指令，而不是整体重写加长。
- 删除互相冲突、重复、无法验证的形容词；每条指令都应能对应一条可观察行为。
- 附 3 条验收断言（例如「无输入时返回固定结构」「不输出代码块外的说明」「字段名恒定」），说明怎么测。
- 标注 token 预算；提示词会随每轮请求重复发送，能省则省，长材料应外置按需加载。
